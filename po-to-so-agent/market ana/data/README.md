# 模擬資料說明（第 3 組・AI 生產訂單轉銷售訂單 Agent）

> 全部為虛構資料，僅供 Demo／提案使用，不含真實客戶、通路或企業訂單。

## 檔案清單

| 檔案 | 說明 | 最低要求對應 |
|------|------|-------------|
| `product_master.csv` | 商品主檔（5 品項） | ≥5 品項 |

## 資料假設

1. **可用量計算**  
   `可分配量 = inventory.available_qty - inventory.reserved_qty + 本生產單同品項 qty`  
   （已 reserved 不可再承諾，避免雙重分配）
2. **可出貨日** = 該品項 `planned_finish_date`（庫存既有量可視為今日可出，Demo 簡化：與生產完成日取較晚者；本組為求清楚，草稿交期以生產完成日為準，既有庫存可提前滿足部分量時於匹配依據註明）
3. **交期可行條件**  
   `可出貨日 ≤ required_delivery_date`；否則標「交期衝突」
4. **匹配優先序**  
   優先級（高>中>低）→ 交期較早者優先 → demand_id 較小者優先
5. **部分出貨**  
   Demo 預設「不自動部分出貨」；數量不足整筆標例外，交人工決定是否削量／拆單
6. **品號必須存在於主檔**；不存在則標「品號不一致」
7. **不寫入正式 ERP**；輸出僅為銷售訂單草稿 + 人工確認

## 建議匹配依據文案範例

**草稿（DEM-001）**  
> 品號 FG-1001 主檔驗證通過；可分配量 1050 ≥ 需求 400；生產批 BAT-260810-A 預計完成 2026-08-10 ≤ 交期 2026-08-12；依優先級「高」分配。待人工確認後建立正式訂單。

**數量不足（DEM-004）**  
> FG-1001 可分配量原為 1050，經 DEM-001 占用 400 後剩餘 650 < 需求 700。建議：削量至 650、拆單、或調其他來源。需人工決裁。

**交期衝突（DEM-005）**  
> FG-1004 數量充足（480≥100），但預計完成 2026-08-15 晚於客戶交期 2026-08-12。建議：與客戶協商延交、改配既有庫存 80（仍不足）、或取消。需人工決裁。
